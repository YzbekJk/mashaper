# Мэшапер

Подгоняет GD Song под обычную песню: тональность GD Song меняется под обычную песню, а темп обычной песни под GD Song.

- Тональность и BPM определяются автоматически, их можно поправить вручную.
- Если у песни нет тональности, питч не меняется.
- Минор и мажор не смешиваются: будет ошибка.
- Граница питча настраивается (0-6 полутонов): если сдвиг больше, Мэшапер предупреждает.
- BPM сравниваются с точностью до удвоения: 65 и 130 считаются одним и тем же.

Всё работает в браузере, файлы никуда не отправляются.

## Мешапы: аккаунты, загрузка, лента (Supabase)

Три вкладки: «Подгонка» (всё, что было раньше), «Загрузить мешап» и «Мешапы» (слушать, лайкать, комментировать, скачивать). Аккаунты, файлы и данные хранятся в Supabase.

Подключение:

1. Создайте проект на supabase.com.
2. Откройте SQL Editor, вставьте весь файл `supabase/schema.sql` и нажмите Run. Он создаёт таблицы, правила доступа (RLS) и хранилища `avatars` и `mashups`.
3. Project Settings -> API: скопируйте Project URL и anon (publishable) key в `config.js`. Эти два значения публичные, доступ защищён правилами из схемы.
4. Authentication -> URL Configuration: в Site URL укажите адрес сайта (https://yzbekjk.github.io/mashaper/), чтобы письма вели на него.
5. По желанию Authentication -> Providers -> Email: выключите «Confirm email», чтобы вход работал сразу после регистрации.

Пока `config.js` пустой, вкладки «Загрузить мешап» и «Мешапы» показывают, что облако не подключено.

## Админ-панель

Кнопка «Админ-панель» лежит в настройках. Пароль в коде сайта и в репозитории не хранится: его проверяет Supabase
(функция `admin_login`), а в базе лежит только bcrypt-хеш. После входа права админа действуют 1 час.

Настройка: выполнить `supabase/admin.sql` в SQL Editor, затем один раз задать пароль запросом
`insert into public.admin_secret (id, pw_hash) values (1, crypt('ВАШ ПАРОЛЬ', gen_salt('bf', 10))) on conflict (id) do update set pw_hash = excluded.pw_hash;`
(этот запрос в репозиторий не кладут).
